# Lexumi — адмінська веб-панель

Проста статична сторінка (без npm/збірки) для наповнення адмінського
контенту (мови → розділи → теми → слова/речення/правила/відео/історії/
картки-зображення/аудіодіалоги) з браузера на комп'ютері — той самий
Supabase-проєкт, що вже використовує Android-застосунок, ті самі
RLS-політики контролюють доступ (`backend/SCHEMA.md`).

## Деплой на Vercel

1. Зайти на [vercel.com](https://vercel.com), увійти через GitHub.
2. New Project → обрати репозиторій `lexumi`.
3. **Root Directory** — вказати `admin-web` (важливо, інакше Vercel
   спробує зібрати весь репозиторій).
4. Framework Preset — **Other** (це проста статика, ніякого build command
   не потрібно; Output Directory лишити порожнім/`.`).
5. Deploy. Автодеплой на кожен push в `main` — за замовчуванням.

## Обов'язкове одноразове налаштування в Supabase (перед першим входом)

Адмінський акаунт зараз існує лише через Google Sign-In в Android-
застосунку — пароля в нього ще немає, а панель логінить лише через
email+пароль (без Google OAuth — це вимагало б окремого Web OAuth
Client ID в Google Cloud Console, зайва складність для v1).

1. Supabase Dashboard → **Authentication → URL Configuration** → додати
   Vercel-домен (той, що дасть Vercel після деплою, напр.
   `https://lexumi-admin.vercel.app`) у **Redirect URLs** — без цього
   лист скидання пароля поведе в нікуди.
2. Відкрити панель → "Забули пароль? / перший вхід" → ввести email
   адмінського акаунта → перевірити пошту → перейти за посиланням
   (веде на `reset-password.html`) → задати пароль.
3. Далі — звичайний вхід email+паролем на головній сторінці.

Якщо потрібен ще один адмін — `update profiles set is_admin = true
where id = '<uuid нового акаунта>'` в SQL Editor (той самий акаунт
має спершу хоч раз увійти в Android-застосунок, щоб рядок `profiles`
взагалі існував).

## Локальний запуск без деплою

**Не відкривайте `index.html` подвійним кліком (`file://`)** — сторінка
використовує ES-модулі (`<script type="module">`), а браузери блокують
їхнє завантаження через `file://` (CORS). Потрібен хоч якийсь локальний
HTTP-сервер, напр.:

```bash
npx serve admin-web -l 5173
```

і відкрити `http://localhost:5173`. Виняток: посилання зі "скидання
пароля" все одно поведе на реальний Vercel-домен (`redirectTo`
фіксований), не на локальний сервер — це нормально, пароль можна задати
один раз через задеплоєну версію, а далі логінитись локально тим самим
паролем.

## Обсяг v1 — що є, а що свідомо відкладено

Є: повний цикл мова→розділ→тема→весь контент, редагування (не лише
додавання й видалення) для правил/слів/речень/відео/історій/карток/
аудіодіалогів/тестових питань — кнопка "Редагувати" підвантажує наявні
значення в ту саму форму, що й додавання (для картинки/аудіофайлу —
лишити поле порожнім, щоб не змінювати наявний файл), дедуплікація
слів/речень (та сама логіка "чи вже є такий термін в мові", що і в
Android — `app/src/main/java/com/lexumi/app/data/repository/RepositoryImpl.kt`),
стиснення картинок до ≤100kb на клієнті (дзеркало
`app/src/main/java/com/lexumi/app/util/ImageCompressor.kt`), реальне
завантаження аудіо в Supabase Storage.

Редагування слова/речення міняє СПІЛЬНИЙ запис (`words`/`sentences`) —
якщо воно використовується в кількох темах, зміна відобразиться в усіх
них. Редагування "перекладу лише для цієї теми" (translation_override)
через панель поки не робиться — для цього рівня деталізації користуйтесь
Android-застосунком.

Відкладено: drag-and-drop переупорядкування (лишається просте числове
`position`), масовий імпорт, прев'ю контенту як в застосунку.

## 2FA (email-код після входу)

Після email+пароля адмін ще вводить 6-значний код, надісланий на його
`profiles.email`, перш ніж бачить саму панель — раз на браузерну сесію
(закрили вкладку/браузер → наступного разу код питає знову). Одноразове
налаштування (нікого з цього ще не зроблено — CLI Supabase в моєму
середовищі немає, тож деплой лише через Dashboard):

1. **Таблиця** — виконати `backend/admin_2fa.sql` у Supabase SQL Editor.
2. **Resend** — зареєструватись на [resend.com](https://resend.com)
   (безкоштовний тариф), скопіювати API-ключ. Сендер за замовчуванням —
   `onboarding@resend.dev` (працює одразу, без підтвердження домену);
   щоб листи йшли з власного домену, підключіть його в Resend і
   поміняйте `RESEND_FROM` у `supabase/functions/send-2fa-code/index.ts`.
3. **Дві Edge Functions** — Supabase Dashboard → **Edge Functions** →
   Create function:
   - `send-2fa-code` — вставити вміст `supabase/functions/send-2fa-code/index.ts`.
   - `verify-2fa-code` — вставити вміст `supabase/functions/verify-2fa-code/index.ts`.
   - Обидві функції імпортують `../_shared/cors.ts` — якщо Dashboard-редактор
     не підхоплює відносні імпорти між функціями автоматично, створіть і
     її як третій файл усередині кожної функції (вміст той самий,
     `supabase/functions/_shared/cors.ts`) або вставте вміст `cors.ts`
     прямо в початок обох `index.ts` замість `import`.
4. **Секрет** — Edge Functions → Manage secrets → додати
   `RESEND_API_KEY` (значення — ключ із кроку 2). `SUPABASE_URL`/
   `SUPABASE_ANON_KEY`/`SUPABASE_SERVICE_ROLE_KEY` Supabase підставляє
   в кожну функцію сам, вручну їх задавати не треба.

## Видалення — soft-delete, не справжній DELETE

Кнопка "Видалити" ніде (крім відео та аудіодіалогів) насправді не стирає
рядок — `deleteRow()` (`crud.js`) проставляє йому `deleted_at`, а
`listRows()`/RLS-політики читання (`backend/SCHEMA.md`) виключають такі
рядки з будь-якої вибірки, тож ефект для користувача той самий. Видалення
мови/розділу/теми каскадно позначає й усе вкладене — крім відео/аудіо
(і їхніх тестових питань), які й далі видаляються насправді (див.
`cascadeDeleteLanguage`/`cascadeDeleteSection`/`cascadeDeleteTopic` в
`app.js`). SQL для додавання цих колонок — `backend/soft_delete_migration.sql`
(виконати один раз у Supabase SQL Editor). Відновлення видаленого через
UI поки нема — лише вручну через Table Editor (обнулити `deleted_at`).
